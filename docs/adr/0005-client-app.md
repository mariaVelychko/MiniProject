# ADR-0005. Клієнтський застосунок (ЛР4): технологія, шар API, ідентифікація користувача

## Статус

Accepted (2026-11-02). Розвиває ADR-0004 (шлюз); ЛР4.

## Контекст

Потрібен клієнт з екранами, формами й станами (консоль не приймається), який працює **лише через шлюз**, не містить
бізнес-логіки й секретів і правильно поводиться при 401, 429, деградації та недоступності сервера.

Проблема, що виявилась під час написання клієнта: **ідентифікатор користувача в Auth (токен) не збігається з `Person.Id`
моноліту**, а Schedule приймає `clientId` у тілі запиту й не має авторизації (ADR-0003). За правилом ЛР4 клієнт
ідентифікатор не надсилає — отже «записатися» й «мої записи» без нового рішення зробити не можна.

## Рішення

| Питання | Рішення |
|---|---|
| Технологія | **HTML + JavaScript (ES-модулі), без збірки й залежностей.** Запуск: `node client/dev-server.mjs` або Docker (nginx). |
| Шар API | `js/api/http.js` — усе, що стосується мережі: адреса з `config.js`, токен, **одна** спроба оновлення при 401 (спільна для паралельних запитів), пауза після 429 за `Retry-After`, таймаут (8 с), нормалізація помилок у `ApiError`. Екрани `fetch` не викликають. |
| Стани екрана | Завантаження (скелетони, кнопки заблоковані) · успіх · порожньо (не помилка) · помилка з «Повторити». |
| Деградація | Складена відповідь `partial: true` → видно наявне й чесно сказано, чого бракує; `sessions: null` ≠ `sessions: []`. |
| Створення без дублів | `Idempotency-Key` генерує клієнт (`crypto.randomUUID()`), лишається тим самим після мережевої помилки/таймауту/503, змінюється після визначеної відповіді або зміни даних. Кнопка заблокована на час запиту. |
| Помилки форм | Поле `errors` відповіді шлюзу показується біля відповідних полів (400, а також 404/409 — біля поля «Тренування»). |
| Ідентифікація | Шлюз отримав **«мої записи»**: `GET/POST/DELETE /api/v1/me/bookings`. Користувач = власник токена: токен → профіль Auth (email) → клієнт у довіднику моноліту (за email) → `clientId` для Schedule. Клієнт надсилає лише `workoutId` та `Idempotency-Key`. Чужий запис створити чи скасувати неможливо. |
| «Статус» запису | У домені статусу немає (скасування видаляє запис), тому шлюз віддає `upcoming`/`past` за часом тренування (`Gateway:LocalUtcOffsetHours`, бо час у Schedule без поясу). |
| Бізнес-логіка | Клієнт показує те, що прийшло: не рахує вільні місця (показує «Записано: 2 з 10»), суми чи знижки; чи можна записатися — вирішує сервер (409). |
| Секрети | У клієнті немає жодних: лише адреса шлюзу в `config.js`. Токени живуть у `localStorage` користувача. |
| Docker | `client` у `docker-compose.yml` (nginx, порт 8080), адреса шлюзу — змінна `API_BASE_URL`. |

## Розглянуті варіанти

* **Blazor / React / WPF замість HTML+JS.** Складність технології на оцінку не впливає; без збірки й залежностей клієнт
  запускається на будь-якій машині й прозоро показує, що саме він робить із мережею.
* **Клієнт надсилає `clientId`.** `−` порушує правило ЛР4 і дозволяє записати будь-кого.
* **Мігрувати всіх користувачів моноліту в Auth.** `+` один ідентифікатор; `−` велика міграція поза межами ЛР4.
* **Schedule сам перевіряє JWT і зіставляє користувача.** `+` правильна межа відповідальності; `−` змінює контракт і
  поведінку наявних маршрутів Schedule (ЛР2/ЛР3 забороняють).
* **Автоматично створювати клієнта в моноліті при першому записі.** `−` шлюз би створював дані предметної області.

## Наслідки

**Отримали:** клієнт без секретів і без адрес сервісів; один запит на екран деталей; захист від дублів і подвійних
натискань; зрозумілі стани для всіх збоїв.

**Заплатили / обмеження:**
* зіставлення Auth → клієнт моноліту за **email**: якщо email у системах різні, шлюз повертає `403 client_profile_missing`
  (демо-дані створює `scripts/seed-demo.ps1`);
* кожен запит «моїх записів» робить додаткові виклики (профіль Auth + довідник моноліту) — це ціна різних ідентифікаторів;
* `upcoming/past` залежить від налаштованого зсуву часу;
* CORS у шлюзі відкрито для всіх джерел (`Cors:Origins`) — для демо; у продуктиві — перелік адрес клієнта;
* офлайн-режим — лише «останній список каталогу» (localStorage).
