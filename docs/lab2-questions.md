# ЛР2 — відповіді на контрольні питання

1. **Шов (seam).** Місце, де систему можна «розрізати», не змінюючи код по інший бік. Шукав так: виписав таблиці й класи, яких
   торкаються `WorkoutsController`/`BookingsController`, і розділив на наші (`Workouts`, `WorkoutParticipants`), чужі
   (`Persons`, каталог) та спільну дрібницю (рядки ролей). Ознака шва — агрегат, який пишуть тільки ці два контролери.
2. **Чому немає FK між БД.** Бази різних сервісів розгортаються, масштабуються й мігрують незалежно; FK зробив би їх одним
   цілим (спільна доступність, порядок міграцій). Замість нього — колонка з Id + перевірка через API власника + знімок даних.
3. **Характеризаційний тест.** Фіксує те, що система робить *фактично* (очікуване = реальна відповідь моноліту), а не те, що
   «має бути» за документацією. Доводить незмінність, а не правильність.
4. **Інтеграційний vs модульний vs e2e.** Модульний — один клас без БД/мережі. Інтеграційний — кілька частин разом
   (контролер + конвеєр + валідація + EF + реальна тестова БД) усередині одного процесу, сусіди — стаби. e2e — усі реальні
   сервіси, шлюз і клієнт.
5. **WebApplicationFactory.** Піднімає застосунок у тестовому процесі й дає `HttpClient` без сокета. У `ApiFactory`
   підмінено: рядок підключення (тестова БД `*_test`), `ICatalogClient` і `IUserDirectoryClient` (стаби з відомими відповідями).
6. **Ідемпотентність.** Повторне виконання з тими самими даними дає той самий результат. `GET`/`PUT`/`DELETE` ідемпотентні
   за специфікацією, `POST` — ні; тому `POST /api/bookings` захищено `Idempotency-Key`.
7. **Дедлайн.** Без нього завислий сусід тримає наш потік/запит необмежено, черги запитів ростуть і падає вже наш сервіс
   (каскадна відмова). З дедлайном (2 с) ми швидко віддаємо `503`.
8. **Знімок назви й ціни.** Інакше зміна ціни/назви в каталозі «перепише» історію. У `Workouts` лежать `Type` і `PriceSnapshot`,
   в `Bookings` — дані клієнта на момент запису.
9. **Перенесення даних і автоінкремент.** SQL-скрипт `INSERT … SELECT` (обидві БД на одному сервері), `Id` тренувань збережено.
   Лічильник піднято вище за `MAX(Id)`, щоб нові тренування не отримали вже існуючі id.
10. **Strangler Fig.** Поступове обплетення моноліту новими сервісами за шлюзом. Зараз — маршрут перемкнено, старий код у
    моноліті ще лишається на час перевірки; далі — його видалення.
11. **Без baseline-файлів.** Дізнатися про зламану поведінку можна було б лише від користувачів (або за ручним порівнянням
    «на око»); саме тому спершу фіксуємо поведінку.
